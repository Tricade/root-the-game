# Runtime and compatibility, ROOT 1.4

- Node.js 24.22.1, no runtime package installation; HTTP API v3 and save schema v3.
- Three.js 0.186.1, git revision `9b4a2ac29c63ccb43fd51c5661f2f873ac2c39b8`. Core and examples are from the same npm package. GLTFLoader, BufferGeometryUtils and SkeletonUtils were inspected in that exact package; import paths alone point to the local core. Original package details: [dependencies.md](dependencies.md).
- Asset package 1.0.0: glTF 2.0, meters, +Y up, +Z front, external relative PBR atlases. LOD1 and collider proxies are omitted from the rendered scene. Dynamic LEDs and door pivots are preserved during static mesh batching.
- The logical 18U operating module (16 device units plus switch/PDU) remains inside the physical 42U cabinet; unused units are reserved blank panels. Imported assets do not invent servers or increase capacity.
- New central-system fields default on old saves. POSTs missing the facility capability are rejected with 409; GET and explicit import still migrate old saves. Modern clients use an optimistic SHA-256 revision, checked atomically inside the persistence queue. A conflict never retries with a newly fetched revision automatically.
- Browser input basis: [UI Events WD 21 February 2026](https://www.w3.org/TR/2026/WD-uievents-20260221/) and [Pointer Lock 2.0 WD 25 February 2026](https://www.w3.org/TR/2026/WD-pointerlock-2-20260225/). Releasing pointer lock does not itself mean leaving the 3D room. Lost focus and visibility clear held movement; missing key-up events also have an expiry. The ordinary mouse-drag path remains available.
- Localization uses MutationObserver per the [WHATWG DOM Standard](https://dom.spec.whatwg.org/#mutation-observers), retaining source strings for reversible switching. User-entered names and input values are preserved. Generated 3D labels and live screen textures use the same locale.
- Dialog layering follows the CSS 2.1 [stacking-context painting order](https://www.w3.org/TR/CSS2/zindex.html), checked for the 3D-upgrade fix. The actual baseline rendered an app modal at 60 behind the fullscreen room at 80. App modals now use 1000, above the room and arrival sequence (999); transient feedback uses 1010 to preserve visible action errors above a modal. These are positioned root-level siblings. Browser interaction/screenshot checks, rather than a CSS text assertion, verify the confirmation and return paths.
- Facility generation: Python 3.12.14 and NumPy 2.5.4 were observed locally; exact official references and the pinned NumPy requirement are in `tools/asset-generator/README.md`. Normal use requires neither Python nor Blender.

Only the selected six-rack room is allocated in the renderer. The limits on saved fleets are protective validation bounds; a maximum-size save test does not establish real-time performance at that size.

The corridor revision also uses the same Three 0.186.1 `BoxGeometry` face-group order and `Texture`/`CanvasTexture` source semantics (inspected in the matching package). Architecture maps are cropped from an actually present `mat_arch_steel` material on the airlock; the older fire-door model has no `mat_arch_wall` material. Cropped maps retain glTF `flipY=false`, base-color sRGB and the normal-map strength already applied by the asset loader. Metric geometry gives one texture tile per two meters. Central rooms are unique on UG 1; floor links are derived from owned room IDs.
